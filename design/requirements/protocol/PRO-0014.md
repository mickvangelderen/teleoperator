# PRO-0014: Protocol message flow

**Tags**: protocol

## Description

The protocol message flow is as follows:

1. version negotiation
2. capability advertising
3. subscription

### Version negotiation

Version negotiation is defined separately ([PRO-0004](./PRO-0004.md)).

### Capability advertising

The server advertises its capabilities ([PRO-0016](./PRO-0016.md)).

### Subscription

A tracking data subscription is specific to a single sample group.
Samples from different sample groups require separate subscriptions.

The client requests a subscription by selecting advertised samples, supported encoding formats, a delivery mode ([PRO-0019](./PRO-0019.md)), and publication settings.
The client assigns a subscription an id according to its own policy.
The subscription id is used to identify sample data.
Subscriptions are immutable except for full replacement by a new request with the same id.

The server may reject a request and should explain why.
The server sends acceptance and any required interpretation metadata over the control channel.
Upon acceptance, the server should immediately publish the current state of the selected samples.
A subscription cannot outlive its connection.

### Unsubscription

The client can request unsubscription over control.
The server can terminate a subscription for any reason.
In either case, the server notifies the client, identifying the subscription and the reason.
