# PRO-0014: Protocol message flow

**Tags:** protocol

The protocol message flow is as follows:

1. version negotiation
2. capability advertising
3. subscription

## Version negotiation

Version negotiation is described in [PRO-0004](./PRO-0004.md).

## Capability advertising

The server advertises its sample groups ([PRO-0012](./PRO-0012.md)), sample descriptors ([PRO-0013](./PRO-0013.md)), and supported publication settings.

## Subscription

The client requests a subscription by selecting advertised samples, supported encoding formats, and publication settings.
A subscription is specific to a sample group.
The client provides an subscription identification that it uses to correlate sample messages to a particular subscription (revision).
Subscriptions are immutable.
The server may reject a subscription request and should indicate why it was rejected.
The server sends acceptance and any required interpretation metadata over control before sending the subscription's samples over the tracking channel.
The server should start publishing requested tracking data for a subscription upon acceptance and does not need to wait for client acknowledgement.
The lifetime of a subscription is tied to the connection and should not survive past it.

## Unsubscription

The client can request unsubscription over control.
If the server terminates a subscription, it sends a control notification identifying the subscription and the reason.
