# PRO-0024: Subscriptions

**Tags**: protocol

## Description

A subscription is a request for samples from a single sample group.

The subscription id is chosen by the client and may for example serve both as an identifier and as a revision.

Changing the selection or channel requires full replacement by a new subscription request with the same id.
The client can change the schedule while the subscription is live.

The messages defined below use the reliable channel ([PRO-0002](./PRO-0002.md)).

The server may reject a subscription request and should explain why.

Upon acceptance of a subscription, the server should immediately initiate publishing, without waiting for client acknowledgement.

A subscription cannot outlive its connection.

The server can terminate a subscription for any reason.

### Subscribe

Client-to-server request to create or fully replace a subscription.

| Field             | Description                                                  |
| ----------------- | ------------------------------------------------------------ |
| `subscription_id` | Client-chosen subscription id.                               |
| `selection`       | `SampleSelection` ([PRO-0025](./PRO-0025.md)).               |
| `channel`         | `Channel` used for publications ([PRO-0019](./PRO-0019.md)). |
| `schedule`        | Initial `DeliverySchedule` ([PRO-0026](./PRO-0026.md)).      |

### SubscriptionAccepted

Server-to-client response accepting a `Subscribe` request.

| Field             | Description                               |
| ----------------- | ----------------------------------------- |
| `subscription_id` | Id from the accepted `Subscribe` request. |

### SubscriptionRejected

Server-to-client response rejecting a `Subscribe` request.
A rejected replacement leaves the existing subscription unchanged.

| Field             | Description                                    |
| ----------------- | ---------------------------------------------- |
| `subscription_id` | Id from the rejected `Subscribe` request.      |
| `reason`          | Optional textual explanation of the rejection. |

### Unsubscribe

Client-to-server request to end a subscription.

| Field             | Description                                    |
| ----------------- | ---------------------------------------------- |
| `subscription_id` | Client-assigned id of the subscription to end. |

### Unsubscribed

Server-to-client notification that a subscription has ended.
Sent after either client-requested unsubscription or server-initiated termination.

| Field             | Description                                        |
| ----------------- | -------------------------------------------------- |
| `subscription_id` | Client-assigned id of the terminated subscription. |
| `reason`          | Textual explanation of the termination reason.     |
