# PRO-0010: Sample formats

**Tags**: protocol

## Description

`SampleFormat` defines the binary representation of sample data.

| Format    | Enum value | Representation                               |
| --------- | ---------- | -------------------------------------------- |
| invalid   | `0x00`     | Never valid                                  |
| `bit`     | `0x01`     | Single boolean bit                           |
| `u8`      | `0x02`     | Unsigned 8-bit integer                       |
| `u16`     | `0x03`     | Unsigned 16-bit integer                      |
| `u32`     | `0x04`     | Unsigned 32-bit integer                      |
| `u64`     | `0x05`     | Unsigned 64-bit integer                      |
| `i8`      | `0x06`     | Signed 8-bit integer                         |
| `i16`     | `0x07`     | Signed 16-bit integer                        |
| `i32`     | `0x08`     | Signed 32-bit integer                        |
| `i64`     | `0x09`     | Signed 64-bit integer                        |
| `f32`     | `0x0A`     | IEEE 754 binary32                            |
| `f64`     | `0x0B`     | IEEE 754 binary64                            |
| `unorm8`  | `0x0C`     | Unsigned 8-bit integer normalized to [0, 1]  |
| `unorm16` | `0x0D`     | Unsigned 16-bit integer normalized to [0, 1] |
| `snorm8`  | `0x0E`     | Signed 8-bit integer normalized to [-1, 1]   |
| `snorm16` | `0x0F`     | Signed 16-bit integer normalized to [-1, 1]  |
| reserved  | *          | Reserved for future use                      |

Press, release, touch, untouch, and revision counters are maintained independently of client subscriptions.
Counters wrap on overflow.

Server implementations are encouraged to obtain transitions from the device APIs when possible instead of reconstructing them from observed samples, since the API implementation may have native support for this.
